One posting, three gates

The same commands for every system. Each prints one JSON line and an exit code your agent can branch on.

  1. read lists the form

    Every field with its id, type, options and whether it is required, so the agent knows what to answer.

    $ uvx atsfill read "$POSTING"
{"status":"ready",
 "system":"greenhouse",
 "fields":[{"id":"level",
   "label":"English level",
   "type":"choice",
   "required":true,
   "options":["Basic","Fluent"]},
   …]}

  2. fill reads every answer back

    A dry run: it fills the form, reads each field back from the page, and never submits. ready means every answer read back as given; a mismatch names the field.

    $ uvx atsfill fill "$POSTING" \
    --answers answers.json
{"status":"ready",
 "system":"greenhouse"}

  3. send submits when all match

    Only on a system you allowed, only once per posting, and only when every answer reads back as given.

    $ uvx atsfill send "$POSTING" \
    --answers answers.json
{"status":"submitted",
 "system":"greenhouse",
 "evidence":"https://job-boards.greenhouse.io/acme/jobs/1234/confirmation"}

Terminal rules

Submitting is off
until you list a system under submit-allowed, in a config file the agent does not write.
One send per posting
A posting already sent is refused unless you pass --resend.
Side effects declared
Some systems save answers as they are typed. atsfill status lists what each one does before anything is sent.
Accounts handled
Where a system needs one, atsfill signs in from your password manager and types emailed codes from your mailbox command.
Telemetry you can turn off
One anonymous event per command, never your answers. What is sent.
